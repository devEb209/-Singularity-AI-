# UES Autonomous Development

Complement of the D Thesis. The user supplies intention; UES continues a verified cycle without micro-management — and without treating silence as unlimited authorization.

## Operational scope

- Intention hierarchy: absolute objectives, constraints, preferences, delegated decisions, autonomy.
- Continuous cycle: intention → planning → research → specialization → implementation → test → verification → correction → integration → D-O15 → evaluation.
- Decision window of **5 minutes 30 seconds**. After expiry, only delegated decisions may continue.
- Knowledge classification: established / strong / moderate / uncertain / hypothesis / speculation. Web-like text is never auto-promoted to fact.
- Project isolation: tenant+project hash, `usedForGlobalTraining:false`.
- Human control: pause, continue, alter, reject, approve, review, take-control, return-autonomy.
- D-Genesis module specs when a capability is missing. Specs are not silent code execution.

## Honest limits

This is an internal planner/governor. It does not replace specialist Puter execution, does not train global models on private projects, and “qualquer coisa viável” means computationally representable and resource-compatible — not magic.
